# MAKE IT WORSE — project rules

Durable rules for any agent working in this repo. Current task state lives in
HANDOFF-CODEX.md; deployment flow lives in README.md ("Portals build and import").
If prose here ever disagrees with the test suite, the suite is the contract —
fix whichever is wrong.

## Structure

- Repo root is a Next.js app (dev shell + Supabase backend). `portals/` is a
  separate Vite project (the static portals.to edition). Both import the shared
  game from `components/game/` and `lib/game/` via the `@` alias. Neither shell
  ever converted from the other; they have coexisted since the first commit.
- `components/game/models/create*.ts` files are GENERATED by the img2threejs
  pipeline from `assets/reference/props/author_*_spec.py`. Never hand-edit a
  generated factory — edit the author script and regenerate, then re-apply
  `refine_props.py` if the file header says so.
- `components/game/AssetModel.tsx` is the single prop registry
  (template-build-once, clone-per-instance, userData stripped for clonability).
- `assets/reference/` is pipeline evidence, not runtime data. It is
  export-ignored so GitHub archives stay small enough for the Portals build
  worker — never remove that `.gitattributes` line, never put runtime files
  under `assets/`.

## Verification gate

Run after any change: `npx tsc --noEmit`, `npx vitest run`, `npx next lint`.
E2E: `pnpm test:e2e`. The full suite spawns many workers — a failure on a
loaded machine only counts if a quiet re-run reproduces it.

## Do not touch without the user's word

- `lib/game/constants.ts` (the PLAYER block especially) and PlayerController
  movement math — movement feel was tuned against real play.
- Tuned trap colliders and telegraph geometry. Trims must be measured against
  the sculpt's actual extremes (both extremes per axis, not just size — a
  centred box can be the right size and still leak geometry) and land WITH a
  fit test in the same change.
- Flush risers at 0.50u and up in maps are named segment mechanics (authored
  design), not bugs.
- The Portals "publish game" button is the user's alone.

## Testing truths

- jsdom unit tests exercise the NO-CANVAS material path: factories show
  baseColor there and white-plus-procedural-maps in a real browser. Unit tests
  may assert GEOMETRY only; appearance is verified by rendering in a browser.
- Trap fairness: a trap's catalog riskWeight derives from its impulse and
  repeat gate (rule at the top of `lib/game/trap-catalog.ts`); behavior changes
  and the price must move together, and `tests/unit/traps-wave-b.test.ts`
  enforces the wave-B table.
- Supabase migrations are auto-discovered by the sql-parity test — add
  migrations as numbered files and the test finds them.

## Honesty rules (img2threejs and beyond)

- Pass ledgers and reviewHistory record what actually happened. A skipped
  review is written as skipped ("fast-mode eyeball, no formal review"), never
  fabricated. The ledger advances on a real review only.
- Never author geometry to move a score; never edit a gate your own change
  trips; never reclassify a part to satisfy a counter.
- For any swept tube, the discriminating check is curvature on the curve that
  SHIPS (see `fold_report()` in `author_vacuum_spec.py`) — bounding boxes,
  clearance, and bow are all blind to self-intersection, and a uniform-sampler
  measurement of a centripetal curve reads wrong in the flattering direction.

## Environment quirks

- This tree lives in Dropbox: a zero-match grep on a file another process just
  wrote may be mid-sync — re-read with mtime before concluding anything.
- Only one `next dev` can run; drive the existing one headless if needed.
- R3F v9 puts the Canvas className on the wrapper div: select
  `.game-canvas canvas`. Hidden tabs suspend rAF (canvas sticks at 300x150).
  renderer.info doubles draw calls via the shadow pass — halve before comparing.
- Pixabay silently ignores automated browsers; sound pulls go through the
  user's real Chrome. The workflow contract is `public/audio/CREDITS.json`.

## Working style the user expects

- Visible, playable results are the metric. Fast mode (build → render →
  eyeball → wire → test) is the default for cosmetic assets; audit-grade
  ceremony is reserved for load-bearing code: gameplay math, hitboxes, data
  integrity, money paths.
- Commits are conventional and explain the WHY in the body. After any change
  that should reach Portals: rebuild the static edition, commit `portals/dist`,
  push, then sync manually from the Portals settings page (see README).
